2 · 术语（本文档只用这几个词）

术语定义
Sandbox应用级的配置与资源句柄：持有一组 Options、Provider、池、审计出口。Open() 返回它。它不是一个虚拟机。
Request一次执行的输入形状（runtime + code/args + 文件 + 限额 + 出网）。值类型，可被 Policy 改写（只收紧）。
Run一次执行的过程及其结果 Report。一次性、结束即清理。
Session一个跨调用存活的隔离环境（绑定业务会话 ID）：同一个 box/容器，磁盘与已装依赖保留。
Provider把 Request 落到某种隔离实现上的插件（boxlite / runsc / container / e2b / stub）。
Isolation该次执行实际生效的隔离强度枚举。与 Provider 有关，与配置要求可能不同 → 差值必须告警。
Admission额度闸：并发数、内存水位、租户配额。决定能否进入 Provisioning。
Policy / Observer / Sink三个介入点：可否决并改写 / 只观察状态变化 / 只接收执行输出流。

4 · 对象模型（先看清「谁是谁」，再看 API）

Application ──1:1──▶ *Sandbox（配置 + 池，进程内共享，并发安全）
    ├─ N 次 ──▶ Run（一次性；Run() 返回即已清理完毕）
    └─ N 个 ──▶ *Session（有状态；由业务会话 ID 决定复用；Release() 归还、Destroy() 销毁）
            └──1:1──▶ Isolation（一个 box / 一个容器 / 一台远端 microVM）

关键区分（旧稿没讲）：Sandbox 不是沙盒环境，是「开沙盒的能力」；真正的隔离环境是 Run 的一次性环境或 Session 绑定的 box。 这就是为什么 Open() 很便宜（只做 Probe），而 Session() 很贵（要 Admission + Provisioning + Booting）。

5 · API 手册（每个方法一张契约卡）

包名 pkg/hno/sandbox；以下即公开 API 全集（v0.2 提案）。每张卡：签名 / 入参 / 返回 / 可能错误 / 调用时机 / 默认值。

5.1 构造与销毁

func Open(ctx context.Context, opts ...Option) (*Sandbox, error)

调用时机：进程启动或首次用到工具时。只做 Probe，不创建任何隔离资源。
入参
ctx 控制 Probe 超时；opts 见 §5.2。未传 WithMinimumIsolation 时默认接受当前可用的最强隔离并在 Status() 中报告实际级别。
返回
*Sandbox（并发安全，进程内单例即可）。
错误
*UnavailableError：Tried []Attempt（每个 provider 的失败原因）+ Fixes []string（可直接复制的修复命令）。 Probe 失败不会返回空对象；调用方拿到的要么是可用句柄，要么是带修复建议的错误。今天 ErrNoProvider 只有一句话，是苦恼源头。
反例
不要在每个 tool call 里 Open：Probe 有 IPC 成本。用单例句柄 + Session。

func (s *Sandbox) Status() Status

非阻塞、无错误。返回选中的 provider、版本、实际 Isolation、能力位、池水位、Profile 摘要。
用途
健康检查、/debug/sandbox、日志首行、CI 断言「生产必须是 MicroVM」。

func (s *Sandbox) Close() error

调用时机：进程退出前。释放池内所有 Session 的底层环境（销毁 box/容器），等待在途 Run 结束（受 WithShutdownGrace，默认 10s，超时则强制 Kill 并在返回的 error 中汇总）。
错误
*CleanupError：残留资源清单 + 清扫器 ID。幂等，可重复调用。

5.2 Option（配置面）

签名语义 / 默认值
WithProfile(Profile)从 profile.yaml 载入全部声明；与逐个 Option 冲突时后写覆盖，并产出 EventConfigConflict。默认无。
WithMinimumIsolation(Isolation)硬要求。低于此级别 → *IsolationError 直接失败，不静默降级。默认 IsolationContainer。
WithLimits(Limits)Timeout(30s)·Memory(512MiB)·PIDs(128)·Output(1MiB)·CPUs(2)。是天花板：Run 只能要求更低。
WithEgress(hosts ...string)出网白名单，默认空=全禁（沿用今天 network none 的默认拒绝语义）。
WithSessionTTL(active, idle)Session 保活：默认 30m 绝对 / 5m 空闲；到期 → EventSessionExpired + 回收。
WithPool(size int)预热/并发上限，默认 max(4, NumCPU)；配合 Admission。
WithPolicy / WithObserver / WithSink注册介入点，注册顺序=执行顺序；见 §7。
WithProvider(name string, p Provider)平台团队插自定义引擎；同名覆盖并告警。
WithSecretMode(m SecretMode)SecretEnv（值进沙盒，默认）/ SecretPlaceholder（BoxLite 宿主侧 MITM 替换，需显式）。
WithAudit(fn AuditFunc)每个 Run 一条 AuditRecord。默认走 slog。执行路径今天完全没有审计，这条是新增硬要求。
WithShutdownGrace(d)Close() 等待在途 Run 的时长，默认 10s。

5.3 一次性执行

func (s *Sandbox) Run(ctx context.Context, req Request, ropts ...RunOption) (*Report, error)

调用时机：无状态代码执行。返回时底层环境已销毁（沿用今天 --rm 的一次性语义）。
Request 构造
Python(code) / Node(code) / Shell(script)，或 Request{Runtime, Argv, Inputs []Input, Workspace *WorkspaceSpec, Outputs []OutputSpec, Egress, Timeout}；Files{path→bytes} 仅作 ≤1 MiB 小文件内联快捷方式保留（见 §13.4）。payload 走 stdin，不进 argv（保留今天的做法）。
v0.3 修订：v0.2 的 Files map[string][]byte 是设计缺陷 —— 它只能把小文件读进内存，装不下一个项目目录，也拿不出执行产物。改成 Inputs（来源式，流式）+ Workspace（目录级，见 §14）+ Outputs（产物声明，见 §13），三者都走 tar/流通道，不经内存 map。
RunOption
WithTimeout·WithWorkspace(dir)·WithEnv(kv...)·WithSink（仅本次）·WithRunID。全部只能收紧 Sandbox 级设置。
返回
Report{ExitCode, Stdout, Stderr, Truncated, TimedOut, Duration, Isolation, Provider, RunID, Artifacts ArtifactSet, Phases []PhaseReport, RunRef}。永远非 nil（除非 panic），即使被否决也带回填的 Isolation/RunID。
错误
*DeniedError（Policy 否决，含哪个 Policy、原因）·*IsolationError（级别不达标）·*QuotaError（额度满，含 Limit/Active）·*UnavailableError·context.Cause·*HookFaultError。
⚠️ 迁移点
今天 toolkit.go:106-115 把 provider 错误塞进结果 map 并 return ..., nil —— 模型、监控、Policy 三方都看不见失败。本 API 必须返回真 error，toolkit 层再做「错误也进 map，但 error 非 nil」的双写。

5.4 有状态会话（BoxLite 的价值全在这里）

func (s *Sandbox) Session(ctx context.Context, id string, sopts ...SessionOption) (*Session, error)

调用时机：多轮 agent 工具调用、需要「轮 1 装依赖 → 轮 2 用」。id 用业务会话 ID（同一 id 幂等复用同一环境）。
行为
存在且活着 → 直接绑定（不发 Provisioning）；不存在 → Admission → Provisioning → Booting。这是唯一会付 1–2s box 启动成本的调用。
错误
*QuotaError（并发 box 满）·*IsolationError·*ProvisionError（镜像拉取/磁盘创建失败，带 Fixes：hno sandbox doctor）·*StaleSessionError（id 存在但底层环境已丢，见下）。

func (x *Session) Exec(ctx context.Context, req Request, ropts ...RunOption) (*Report, error)

复用已启动的环境执行一段代码。语义与 Run 一致，但不销毁环境、不重置磁盘。
额外错误
*StateError：当前 Session 不在 Ready/Busy 状态（见 §6.2 可用性矩阵）。

func (x *Session) Files() FileService   // 文件接口，与执行环境同一个根

方法集：Write(ctx,path,data)·Read(ctx,path)·List(ctx,path)·CopyOut(ctx,path) (io.Reader)·Stat(ctx,path)
约束
路径受 file.Sandbox 同套约束（os.Root 语义 + 大小上限），越界一律 *PathError，不猜。这解决今天「执行沙盒与文件沙盒是两套世界、E2B workspace 直接 not implemented（e2b.go:101）」的问题。
Provider 不支持时
返回 *CapabilityError{Missing: CapFileBridge}，明确说「该引擎不支持」，而不是静默走宿主磁盘。

func (x *Session) Release(ctx context.Context) error  |  Destroy(ctx) error

Release＝停止占用、保留磁盘、允许同 id 再绑定（默认由 TTL/idle 自动做）；Destroy＝立即销毁环境。开发者一般都不用手调：交给 TTL。

func (x *Session) State() SessionState

只读快照：State + Age + IdleFor + Isolation + Execs 计数。给 UI 和指标，不驱动逻辑。

5.5 诊断（替代旧稿的 doctor 概念，API 形态）

func Diagnose(ctx context.Context) (*DiagReport, error)

调用时机：CI 起步、部署前、用户报障。不创建任何隔离资源，纯检查。
检查项
/dev/kvm 存在与可写 · HVF 可用（macOS）· bundled bwrap/seccomp 可用 · 镜像是否已缓存 · sidecar/REST 端点可达 · guest 与 SDK 版本匹配 · 磁盘水位 · 出网代理连通。
返回
DiagReport{Checks []Check, Reached Isolation, Fixes []string}；Check{Env string; Want, Got string; OK bool; Fix string} —— 每条失败都带一行可执行命令，不是错误码。
CLI
hno sandbox doctor [--require-isolation microvm]：非零退出码给 CI 用。

5.6 Provider 侧接口（平台团队才看）

签名契约
Probe(ctx) (Info, error)必须不创建资源、不产生费用；Info{Name,Version,Isolation,Capabilities}。失败原因要可展示给用户。
Capabilities() CapabilitySet位标记：CapSession · CapFileBridge · CapEgress · CapStream · CapPTY。Core 按断言决定能用哪些 API，不支持就 *CapabilityError，绝不模拟。
Start(ctx, Spec) (RunRef, error) / Wait(ctx, RunRef, sink) (Report, error) / Kill(ctx, RunRef)三段式；Wait 必须响应 ctx 取消并保证资源回收。
optional SessionHost / FileBridge / EgressHostGo 接口断言实现。旧稿的 SessionSandbox/FileTransfer/EgressPolicy 统一收敛成这三个名字。

兼容：现有 pkg/hno/tools/run 的 Executor（只有 Run+Close）保持冻结，由 provider/legacy 适配成 IsolationContainer 或 MicroVMHosted。旧调用不改一行，新 API 独立包 —— 所以是 v3.1.0。

关键：产物是声明出来的，不是猜出来的。Project.Artifacts = []ArtifactSpec{Path, Kind, Required, MaxBytes}； Core 只收集被声明的路径，未声明一律丢弃并计数（防「产物炸弹」把宿主磁盘打满）。Required 缺失 ⇒ *ArtifactMissingError，不返回半成品。

设计边界：Observer 与 Sink 是数据，不是控制流。需要「拦截/改写/授权」的地方一律走 Policy —— 否则半年后回调链会变成没人敢动的第二套业务逻辑。

        {Path: "dist",        Kind: Dir,  Required: true, MaxBytes: 64 << 20},

语义定义
同一工作区所有 Phase 共享文件系统与环境变量累积（装一次依赖，后面都可用）—— 这正是有状态 Session 的价值

Required=false失败继续跑下一个 Phase（lint/test 常见），FailedPhase 如实记录
FailOpen该 Phase 非零退出视为可接受，不算 err

13.4 与文件 API 的分工（避免两套重复能力）

API用途规模
Session.Exec(req)跑代码；req.Files 内联小文件（≤ 1 MiB/个，总量 ≤ 8 MiB）小、快、单文件
Session.Files().*点状读写：Read/Write/List/Stat（带 offset/limit 流式）中等；maxBytes 约束
RunProject / FromDir / FromArchive整棵树进出，tar 流式，不受内联上限大、目录、可复现

三条硬规则：(a) 内联 req.Files 超限 → *TooLargeError 并提示改用 Project； (b) Files() 与 Project 工作区同一个根，路径语义一致（沿用 os.Root 约束，越界一律 *PathError）； (c) 大目录不允许经 map[string][]byte 传递 —— 只能流式。

16 · 失败分类与重试预算（异常处理的正解不是「多试几次」）

原则：先分类，再决定谁重试、重试什么、拿什么状态重试。不分类的重试＝掩盖 bug + 重复副作用 + 烧钱。

16.1 七类失败（FailureClass）与默认处置

Class判定依据自动重试由谁重试处置
ClassUserCode退出码非 0，且无资源/infra 证据（Traceback、assert、command not found）绝不agent 模型回环给模型自我修正：Failure.NextAction=model_fix + stderr 摘要。自动重跑同样代码只会拿到同样结果
ClassDeniedPolicy 否决 / 审批未过绝不人返回被拒规则 + 需补的授权项（NeedApproval）。同 Request 重试必然同样被拒
ClassPermanent能力不支持、版本漂移、镜像 digest 不存在、Profile 非法绝不—立刻短路 + 命令式修复建议（Remediation()）
ClassTransient引擎 RPC 抖动、连接重置、REST 5xx、镜像拉取网络失败、boot 竞态是（退避+jitter）Core只重试无副作用步骤（probe / pull / copy / status poll）。默认 2 次
ClassResourcequota 满、宿主水位、池空、磁盘不足排队重试（独立预算）Admission不是快速重试，是 backpressure：WaitForSlot + 上限；超了失败并告警
ClassTimeoutTimedOut：Kill 或 detach 超时条件重试调用方语义未知：可能已跑完一半。只有 EffectPure 才自动重试；否则要 RollbackToPhase
ClassLostVM 死/引擎崩/宿主重启（*LostError）重建后重试Core + 调用方OnLost{FailFast | RebuildFromSpec | RestoreSnapshot}。只有输入声明化（§13.1 五种 Source）才能安全 Rebuild
类型化后直接喂给框架已有的 graph.RetryConfig.ShouldRetry func(error) bool（graph/policy.go:22-29，full-jitter 已落地）：沙盒不自建第二套退避引擎。

16.2 重试职责分层（避免 2×3=6 次指数放大）

层重试对象默认预算禁止
Core（沙盒）引擎控制面步骤：probe、镜像解析、盘创建、vsock 连接、status poll、产物传输Attempts=2，backoff 100ms×2 + 20% jitter，总墙钟 ≤ 3s不得重试用户代码
Graph 节点策略整个 Stage / Phase（含已 boot 的 Session 内 Exec）RetryConfig{MaxAttempts:3, PerAttempt:true}，由业务声明不得与 Core 预算相乘：Core 耗尽后向上传 *TransientError，节点层若已耗尽则直接失败
Agent / 模型「改代码再试」——这是新一轮工具调用，不是重试受 model 循环的 max_iterations 约束不得复用同一 payload 静默重跑
人工审批、补出网白名单、换 tier—不得被 unattended 循环代跳

⚠️ 具体陷阱：TimeoutConfig.PerAttempt（policy.go:45-47）对沙盒是必须的 —— BoxLite 一次 boot 要 1–2s， 若按「整节点」算超时，第二次 attempt 一定假超时。所以每次 attempt 预算 = boot + exec，并在 Profile 里显式拆 SetupTimeout / ExecTimeout。

16.3 副作用闸门（EffectClass，v0.3 只提了名词，现在给语义）

EffectClass含义允许的重试方式
EffectPure只算不改（读数据、算指标、打印）任意次重试，可跨 VM 重建
EffectWorkspace只改沙盒内文件/已装依赖重试前须 RollbackToPhase 或 Rebuild；否则重复 pip install 会漂移
EffectExternal有外部可见动作：写回宿主、推 git、发 HTTP、提交 PR、写库不自动重试只允许 AtMostOnce + 幂等键去重
// 幂等 journal：判「这个 key 是否已经真的执行过」，重启后仍然有效
req := sandbox.Request{Runtime:"python", Code: pushPy,
    IdempotencyKey: "pr-8421-publish", Effect: sandbox.EffectExternal, Deliver: sandbox.AtMostOnce}
rep, err := sb.Run(ctx, req)
// journal 命中且状态=Done ⇒ 直接返回上次结果（Republished=true），不重跑
// journal 命中但状态=Uncertain（提交后断连）⇒ *UncertainOutcomeError，禁止自动重试
机制契约
Deliver 语义AtMostOnce（不确定就失败）· AtLeastOnce（可重放，接收方需去重）· ExactlyOnce（best-effort：journal + 幂等键）
Journal 落哪{key → runID, state, payloadHash, resultRef, updatedAt} 进 store.Store / Checkpointer；payloadHash 不符 ⇒ *IdempotencyConflictError，不覆盖
UncertainOutcome提交后断连必须先用 RunRef 查终态（能力位 CapQueryStatus）；引擎查不到 ⇒ 标 Uncertain 并禁止自动重试

16.4 状态感知的重试：Snapshot / Rollback（复杂场景的真正答案）

sess, _ := sb.Session(ctx, bizID)

       sandbox.ClassOf(err) == sandbox.ClassLost {
        sess.Restore(ctx, cp)                    // 回滚到 Phase 边界再试，不重跑 setup

RetryMode行为前提成本

RollbackToPhase回到上一个 Checkpoint 再跑该 PhasePhase 边界已打快照CoW 快照，便宜
ForwardsOnly不重跑，只续跑后续 Phase / 只重新收集产物失败在收集阶段零算力
为什么这条最值钱：「有状态沙盒 + 有副作用的重试」是矛盾的，除非你能把状态退回某个已知点。 CoW 快照让「退回后重试」成本接近零，于是 EffectWorkspace 也能安全自动重试 —— 否则只能退化成「不重试，报错给模型」。

17.3 偶然状态的两种处理：Lockdown（禁）与 Drift（测）

模式做法可靠性 / 代价
lockdown: enforce
（生产 / 需要可靠 Rebuild）		Exec 内直接装包会失败 —— 实现手段是断源而不是 ptrace：包管理器域名不在 allow_net，或 Policy 拦 pip|npm install 类 argv；要装东西只能走 Install()最强：spec 即完整真相
代价：模型偶尔会撞到，需在 Failure.Hint 里教它改用 Install
lockdown: detect
（默认，开发体验优先）		渲染完成后抽样指纹（site-packages 顶层清单、node_modules 顶层、dpkg status hash），Exec 后比对 → Session.Drift() (DriftReport, error)能发现「环境已偏离 spec，Rebuild 后行为可能不同」，不保证抓全（改系统配置、写 /etc 都可能漏）
lockdown: off不检不拦等于放弃 #9 的前提；Diagnose() 应报「Rebuild 语义不可靠」
诚实标注：detect 是尽力而为的告警，不是保证。要「重建后一定等价」就只有一个办法 —— enforce。别把 detect 写成安全边界。
